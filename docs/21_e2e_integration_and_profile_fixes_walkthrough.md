# 21. E2E API 통합 연동 및 개인정보/설정 버그 완전 교정 🚀

본 문서는 프론트엔드와 백엔드 간의 모든 핵심 엔드포인트를 교차 정밀 조사(Audit)하고, 그간 연동되지 않거나 비활성화되어 있던 설정 영역과 버그를 100% 정상 통합 연동한 기술 명세 및 가이드 문서입니다.

---

### 1. 💬 AI 챗봇 서비스 연동 및 통신 규격 정밀화 (`ChatService`)

그간 모의 데이터로만 움직이거나 스펙 불일치로 발생하던 챗봇 통신 장애 요인을 완벽하게 해결했습니다.

*   **챗 세션 목록 타입 주입 에러 해결 (`getSessions`)**:
    *   **문제**: 백엔드는 고정방과 최근방이 구별된 `{pinnedSessions: {...}, recentSessions: {...}}` 형태의 맵 DTO를 반환했으나, 프론트엔드가 즉시 단일 `List` 캐스팅을 시도해 화면 진입 시 크래시가 났습니다.
    *   **해결**: 두 그룹을 완벽하게 파싱·병합하여 고정된 방이 상단에 뜨도록 재정렬하고, 날짜 속성 키(`lastMessageAt` ➡️ `updatedAt`)를 매핑하여 앱이 튕기지 않고 모든 세션이 자연스럽게 연동됩니다.
*   **AI 답변 전송 규격 정밀 보정 (`sendMessage`)**:
    *   **문제**: 프론트엔드에서 AI 질문 내용을 `content` 키로 보냈으나 백엔드는 `@NotBlank`가 선언된 `question`을 요구하여 **400 Bad Request**가 반환되었습니다. 또한 응답 구조에서도 AI 답변이 중첩된 `assistantMessage` 내부에 있어 파싱 에러가 발생했습니다.
    *   **해결**: 전송 바디 키를 `question`으로 전면 보정하고 응답 DTO에서 `assistantMessage` 데이터만 언팩(Unpack)하여 채팅 거품창에 답장이 실시간으로 무결하게 렌더링됩니다.
*   **과거 대화 이력 조회 최적화 (`getMessages`)**:
    *   **문제**: 백엔드에 존재하지 않는 경로인 `GET /chat/sessions/{id}/messages` (404/405 에러)를 호출하고 있었습니다.
    *   **해결**: 백엔드 정식 세션 상세조회 API인 `GET /chat/sessions/{id}` 호출로 변경하고 내부의 `messages` 이력 리스트만 안전하게 정제해 과거 대화방을 완벽히 복원합니다.
*   **좋아요/싫어요 피드백 백엔드 실시간 전송 구현 (`submitFeedback`)**:
    *   **문제**: 기존 버튼은 클릭하면 로컬 UI만 변할 뿐 실제 서버로 요청을 보내지 않는 껍데기 코드였으며 규격 또한 불일치했습니다.
    *   **해결**: 백엔드 `SubmitChatFeedbackRequest` 규격에 정확히 대입하여 `LIKE` 전송은 물론, 싫어요 클릭 시 선택한 사유 인덱스에 따라 **백엔드 매핑 Enum 코드(`INACCURATE_INFO`, `TOO_COMPLEX`, `IRRELEVANT_ANSWER`)** 및 상세 텍스트가 실시간 전송되도록 생명을 불어넣었습니다.

### 2. 🏠 홈 대시보드 및 공모주 매력지수 연동 (`IpoService`)

*   **매력지수 탭 터치 시 빈 리스트 출력 오류 해결**:
    *   **문제**: 홈 화면(`home_screen.dart`)은 내부 렌더링 시 `_homeData['attractiveness']['items']` 구조를 기반으로 루프를 돌았으나, 서비스 클래스에서는 백엔드 응답을 일방적으로 풀어헤쳐 `'attractivenessItems'`라는 엉뚱한 임의의 키로 담고 있었습니다. 이로 인해 탭을 바꿀 때마다 리스트가 빈 공간으로 나타나는 심각한 버그였습니다.
    *   **해결**: 백엔드가 전달하는 원형 계층 DTO 구조(`attractiveness`)를 온전히 살려 전달하면서, 하위 호환성 전용 콤팩트 키(`attractivenessItems`)까지 동시 바인딩하여 **메인 화면의 공모주 탭 카드가 깨짐 없이 완벽하게 동작**합니다.

### 3. 📅 캘린더 공모 데이터 파싱 고도화

*   **개별 쿼리 파라미터 분할**:
    *   기존 `'YYYY-MM'` 문자열 파라미터를 백엔드가 수용하는 정수형 `year` 및 `month` 개 개별 쿼리 인자로 쪼개 전송하여 **500 내부 에러를 완전 차단**했습니다.
*   **다차원 리스트 복원**:
    *   응답에 포함된 계층형 `CalendarMonthResponse` 구조(`calendarCells` 및 `selectedDateSection`)를 완벽하게 해체 및 정규화하여 달력 날짜 칸마다 배정된 경쟁률 및 주간사 텍스트가 세밀하게 뿌려집니다.

### 4. 👤 개인정보 및 설정(마이페이지) 버그 교정

*   **알림 업데이트 HTTP Method 교정**:
    *   `PUT`으로 잘못 선언되어 발생하던 405 Method Error를 백엔드 컨트롤러 `@PatchMapping("/notifications")` 사양과 완벽히 부합하도록 `PATCH` 메소드로 정정했습니다.
*   **회원탈퇴(Withdraw) 바텀 시트 및 API 일치화**:
    *   **문제**: 회원탈퇴 버튼 클릭 시 단순 일반 행 위젯으로 감싸져 있어 터치 반응이 없었고, 연동 경로 또한 엉뚱한 `/auth/withdraw`로 설정되어 있었습니다.
    *   **해결**: 탈퇴 행을 `InkWell` 터치 위젯으로 감싸고 **안전한 경고형 모달 바텀 시트(Modal Bottom Sheet)**를 새롭게 설계해 비밀번호 입력을 유도합니다. 비밀번호가 입력되면 백엔드의 실제 계정 파괴 포스트 엔드포인트(`POST /users/me/withdraw`)를 안전하게 트리거하고 자동으로 세션을 클리어한 뒤 로그인 페이지로 안내합니다.
*   **내 정보 이동 및 실시간 비밀번호 변경 기능 완료**:
    *   **문제**: 상단 프로필 카드 터치 시 내 정보 화면으로 진입하지 않았고, `ProfileScreen` 내의 비밀번호 저장 또한 작동하지 않았습니다.
    *   **해결**: 카드 전체에 `InkWell` 네비게이션 액션을 걸어 `ProfileScreen`으로 이동하도록 고리를 만들었으며, `ProfileScreen`을 `StatefulWidget`으로 완벽히 리팩토링하고 3단계 패스워드 검증(현재 비밀번호, 새 비밀번호, 확인 비밀번호 동일 여부)을 거쳐 백엔드 `PATCH /users/me/password`를 호출해 **실제 데이터베이스 비밀번호가 안전하게 변경**되도록 연동 완료했습니다. **보안 모범 규격을 따라 비밀번호가 성공적으로 변경되면 세션을 자동 로그아웃한 뒤 새로운 비밀번호로 다시 로그인하도록 로그인 화면으로 리다이렉트 처리**합니다.

### 5. 🔄 앱 재시작 시 자동 로그인(세션 복구) 지원

*   **문제**: 기존에는 앱을 완전히 껐다 켤 때마다 `main.dart`에서 로그인 여부를 확인하지 않아 매번 온보딩(로그인 전 화면)으로 초기화되는 불편함이 있었습니다.
*   **해결**: `AuthService`에 `restoreSession()` 로직을 신규 구현하고, 앱 진입점(`main.dart`)의 `runApp()` 이전에 배치했습니다. 이제 앱이 켜질 때 로컬 기기에 저장된 JWT Access Token이 있는지 감지하며, 유효한 토큰일 경우 백엔드에서 사용자 프로필을 즉시 동기화해 **온보딩 화면을 건너뛰고 곧바로 로그인된 홈 화면(MainScreen)으로 매끄럽게 진입**합니다. 만약 만료되거나 유효하지 않은 토큰이면 깔끔하게 찌꺼기를 지우고 정상적으로 로그인 화면을 노출합니다.
